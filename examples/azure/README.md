# `examples/azure/` — day-2 Azure manifests

> **Every file in this directory is a DISABLED EXAMPLE.**
> ADLC never reads, compiles, applies or executes any of them. No ADLC code path
> references them. With no Azure environment variables set, `adlc doctor`
> reports every Azure adapter as unavailable and the spine's credential-free
> defaults run instead. Using anything here requires an Azure subscription and
> deliberate action by you.

## Regenerating the Foundry manifest

`foundry-hotfix-agent.yaml` is produced by the adapter, and a test asserts the
committed file matches. After changing `src/adlc/adapters/daytwo/foundry.py`:

```bash
python -c "from pathlib import Path; from adlc.adapters.daytwo.foundry import FoundryHotfixAgent; FoundryHotfixAgent().render(Path('examples/azure/foundry-hotfix-agent.yaml'))"
```

## On accuracy

Every Azure API name, field name, CLI flag, role name, enum value and numeric
limit used in this directory was verified against `learn.microsoft.com` on
**2026-08-19**, and each file cites the page it came from. Where a claim could
**not** be verified it is labelled **UNVERIFIED** together with the pages that
were searched. Nothing here is a plausible-sounding guess.

The consolidated list of unverified items is in
[`docs/day2-operations.md` §7](../../docs/day2-operations.md#7-sources).
